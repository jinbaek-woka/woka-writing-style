# 한국어 문서 문체 규칙 (woka-writing-style)

Woka 구성원의 Claude Code에 공통 적용되는 한국어 문서 문체 기준이다. Woka 구성원이 내보내는 자료는 AI/AX 강사와 임원의 톤을 기준으로 하며, 학습자(임원, 실무자)와 고객에게 가는 자료가 격식을 잃으면 신뢰가 떨어진다. 이 파일이 문체 규칙의 정본이며, 세션마다 항상 적용된다.

## 적용 범위

- 적용 : 문서 산출물의 한국어 본문(헤딩, 표 셀, 콜아웃, 불릿 포함). 보고서, 제안서, 기획안, 이메일, 노션 페이지, 강의자료, 발표자료, 공지문 등 모든 한국어 산출물.
- 기본 미적용 : 일상 대화, 채팅 답변, 진행 보고, 역질문 답변. 사용자의 CLAUDE.md(전역 또는 프로젝트)가 채팅 답변에도 적용한다고 정하면 그쪽을 따른다.
- 항상 미적용 : 코드, 주석과 로그, 사용자 원문 인용, 사용자가 "구어체 OK", "원문 그대로"라고 지시한 경우.

## 차단 1 감성과잉

- 호명("여러분", "함께"), 격려, 감탄("도전해보세요", "성장의 기회", "이제 시작"), 의미 부풀리기("효과적으로", "성공적으로", "완벽하게", "강력한") 금지
- "극대화"는 한자어 격식 표현으로 허용
- 마무리는 다음 행동 한 줄로 종결

## 차단 2 구어 비유 동사

다음 비유 동사가 본문에 들어가면 즉시 격식 대체어로 교체한다. 표에 없는 비유도 새로 만들지 않는다. 기존 글을 다듬을 때는 한 번만 쓰인 비유도 일반 어휘로 바꾼다. 개념 설명용 비유(책상, 출입증, USB 허브 등)와 공간 이동 비유("자리로 가다")도 대상이며, 실제 동작(손을 들다)과 굳은 관용 표현(진행이 막히다)만 둔다. 출력에 자주 섞이는 셋(못박다, 굴리다, 손대다)은 출력 직전 반드시 재확인한다.

| 구어 표현 | 격식 대체어 |
|---|---|
| 굴리다 | 적용, 진행, 운영 |
| 돌리다 | 진행, 한 차례 진행, 완주 |
| 못박다 | 고정, 한정, 특정, 지정 |
| 손을 대다 | 참여, 기여 |
| 한 발씩 | 부분적으로, 각자 일정 부분씩 |
| 들고 가다 | 가지고 가다, 보여주다 |
| 잡아두다 | 정리, 확인 |
| 돌아가다(작동) | 동작, 작동 |
| 거들다 | 참여, 보조 |
| 박다, 박혀 있다 | 넣다, 삽입, 담다, 반영 |
| 꺼내 쓰다 | 불러오다, 사용, 자동 적용 |
| 굳히다(등록) | 등록, 저장 |
| 쌓아두다(저장) | 등록해두다, 저장해두다 |
| 닿아 있다(관련) | 관련된, 연관된 |
| 닫다, 닫아 두다(확정) | 확정, 미리 정해 두다 |
| 쓰다(글, 문서) | 작성하다 |
| 쓰다(도구, 방법) | 사용하다 |
| 문턱(기준) | 기준 |
| 깎이다(정보, 세부) | 빠지다, 줄다 |
| 흐려지다(결과) | 부정확해지다, 정확도가 떨어지다 |
| 비대해지다(대화 기록) | 길어지다 |
| 소환(에이전트) | 사용, 호출 |
| 적다, 적기(실습 지시문) | 작성하기 |

"적기"는 메모 어감이라 격식 자료에 맞지 않는다. 목적어가 추상 명사면 "예상되는 차이 작성하기"처럼 낱말을 보정하고, 같은 콜아웃의 "고르기", "바꾸기"와 "~하기" 꼴을 맞춘다.

## 차단 3 종결 문체

- 줄글(서술 문단) : 존댓말(~습니다/~합니다)
- 개괄식(불릿, 표 셀, 슬라이드 정리) : 개조식(한자어 명사 종결, 조사 생략, '및' 연결)
- "~예요, ~죠, ~거든요" 구어 종결과 반말 금지. 한 덩어리 안에서 종결 혼용 금지
- 개조식은 글자를 줄이는 것보다 문장이 전하려는 뜻을 정확히 옮기는 데 초점(예 : "튜터가 자리로 갑니다" → "기술 튜터 지원 예정". "튜터 자리 지원"은 뜻이 불분명함)
- 개조식(명사 종결)이 아닌 평서문은 제목, 한 줄 문장, 퀴즈 진술을 포함해 경어체
- 지시, 권유문 : "~하세요", "~합니다", "~하시기 바랍니다" 셋 가운데 상황에 맞춰 선택. "~십시오" 금지
- 질문 : 제목, 점검 항목, 본문 모두 문어체 "~는가". "~습니까" 금지("~입니까" 제목은 청중에게 묻는 말투가 되어 어색)
- 해요체(~요)와 반말 의문(~나, ~ㄹ까) 금지. 예외는 지시 예문, 직접 인용, 학습자가 따라 적을 기입 예시
- 화면 문구(구글 슬라이드, HTML 프레젠테이션)에서 청중과 학습자에게 건네는 권유, 지시문 : "~해 보세요, ~하세요". "~십시오" 금지(아래 "화면 문구 예외" 절)
- 예고문 : 화자(강사, Claude)가 지금부터 할 행동을 예고하는 문장과 학습자와 함께 진행하는 실습 안내는 "~겠습니다"(살펴보겠습니다, 확인하겠습니다, 만들어 보겠습니다, 작성하겠습니다, 사용하겠습니다). "~하겠습니다"와 "~해 보겠습니다" 둘 다 허용하며, 시도의 뜻이면 "~해 보겠습니다" 선택. "~봅니다, ~해 봅니다, ~씁니다" 같은 현재형 예고 금지(현재형 예고는 번역체처럼 읽히고, "~겠습니다"가 강의 말투에 맞음). 동사는 차단 2대로 바꾸고 어미만 "~겠습니다"로 유지
- 사실과 기능을 설명하는 문장("누르면 저장됩니다") : "~합니다/~입니다" 유지("~되겠습니다"는 추측 뜻이 됨)
- 화면 문구의 실습 지시 : 문형표("~해 보세요") 유지

## 차단 4 표식 라벨 금지

"한 줄 요약:", "정리하면 —", "결론부터 —", "TL;DR" 같은 라벨+줄표/콜론 머리말을 본문 어디에도 쓰지 않고 내용을 곧바로 쓴다.

## 차단 5 번역체

잣대는 하나, "이 문장을 팀장에게 말로 보고한다면 이렇게 말하는가". 말로 하면 어색한 문장이 번역체다. 조사 직역(~을 통해, ~에 있어, ~에 대한, ~로부터, ~에 의해)만이 아니라 문장 뼈대와 낱말 결합까지 본다.

- 추상명사 주어 금지 : "소모가 쌓입니다"→"에너지가 소모됩니다", "지칩니다" / "불편이 존재합니다"→"불편합니다", "불편이 생깁니다" / "증가가 관찰된다"→"늘었다"
- there is, 가주어 직역 금지 : 존재하다, 이루어지다, "~하는 것이 가능하다/필요하다/중요하다" → 있다, 했다, "~할 수 있다/~해야 한다/~이 중요하다"
- 연어 위반(한국어에서 서로 붙지 않는 명사+동사) 금지 : 소모가 쌓이다, 효율이 발생하다, 영향을 가하다 → 굳어진 사무실 연어로(피로가 쌓이다, 효율이 오르다, 영향을 주다)
- 영어 추상명사 직역 어휘(측면, 차원, 영역, 접근, 관점, 요소) : 문장으로 풀거나 삭제
- 개조식(불릿, 표 셀, 카드) : 명사 종결이 불가피하므로 느슨히 적용("불편 발생", "에너지 소모" 허용). 줄글은 전부 적용
- 셈 단위 군더더기 금지 : 수량이 요점이 아닌 자리에 "하나", "한 줄", "한 가지"를 붙여 명사구나 문장을 끝내지 않는다. "업무 결정 하나를 분류나 회귀 질문으로"→"업무 결정을 분류나 회귀 질문으로", "숫자 하나 고르기"→"숫자 고르기", "예상 한 줄 작성하기"→"예상 작성하기", "결정이 하나 있다"→"결정이 있다". 수사는 세는 것이 지시의 핵심이라 학습자 행동이 달라질 때("기준 두 가지 작성하기", "3문항")만 유지. 학습목표, 제목, 실습 지시문에서 특히 재확인
- 정밀 교정표와 지적 표본은 humanizer 스킬의 references/formal-mode.md "번역투 정밀 교정표"에 있음

## 차단 6 줄표 금지와 쌍점

"—"(em dash)와 "―"(줄표)를 본문, 제목, 불릿, 표 셀 어디에도 쓰지 않는다. 한국인이 손으로 쓰는 글에서는 거의 쓰이지 않고 AI 글의 신호로 읽히기 때문이다. 대체는 줄표가 하는 일을 보고 정한다.

- 대체 기준 : ① 앞뒤가 각각 완결된 문장이면 마침표 ② 뒤가 부연, 근거, 단서이면 괄호(그 줄에 괄호가 이미 있으면 마침표로 끊거나 문장을 다시 짠다) ③ 앞이 조사 없이 끝나는 명사구 표제이고 뒤가 그 내용이면 쌍점 ④ 위 셋이 모두 아니고 같은 줄에 다른 쉼표가 없을 때만 쉼표
- 쌍점은 양쪽 한 칸씩 띄워 "제목 : 설명" 꼴로 사용(규정의 앞 붙임보다 가독성 우선). 시각과 비율(10:20, 65:60), 코드, URL, 파일 앞머리(frontmatter) 값 안은 예외로 붙임. 기존 글을 다듬을 때는 붙여 쓴 쌍점도 띄움으로 고침
- 한 줄에 층이 같은 쌍점은 하나만. "1단계 : CLI 설치 : 내용"처럼 연달아 쓰지 않는다. 안쪽 표제는 공백으로 붙이고("1단계 CLI 설치 : 내용") 부연이면 괄호, 뒤가 설명의 이어짐이면 마침표. 구분 기호로 갈린 병렬 라벨("역할 : A / 목표 : B")만 예외
- 조사 뒤에는 쉼표를 두지 않는다. 줄표 앞이 조사(은, 는, 로, 에 등)로 끝나면 부호 없이 이어 붙인다("HTML 파일은 나만 볼 수 있습니다"). ④ 쉼표는 앞이 명사나 부사구일 때만
- 제목 안 "A — B" : 뒤가 단서, 금지, 범위이면 괄호("구글, 노션은 CLI만 사용(MCP 금지)"). 뒤가 대등한 어구이면 쉼표. 앞이 명사구 표제이고 뒤가 그 내용이면 쌍점. 뒤가 완결된 서술문이면 제목을 다시 짠다
- " - "를 줄표 대용으로 쓰지 않는다. 범위와 연결의 붙임표(서울-부산, 3-78쪽)는 허용. 표 셀 빈칸은 붙임표 한 글자. 코드, 명령어, 사용자 원문 인용, 캘린더 제목이나 메일 제목처럼 저장소 밖 실물과 글자가 같아야 하는 문자열은 예외

## 차단 7 가운뎃점 금지와 나열 절제

가운뎃점("·")을 쓰지 않는다. 항목을 잇는 부호는 ", "이며, 여러 항목이 한 덩어리로 읽히는 묶음이라도 쉼표를 쓴다(규정이 허용하는 가운뎃점 묶음 표기보다 쉼표 통일 우선). 예외는 쉼표로 풀면 뜻이 달라지는 굳어진 표기뿐이다("3·1절", "6·25" 같은 관용 고유 표기. "수출·입"처럼 공통 성분을 줄인 말은 가운뎃점 대신 "수출입"이나 "수출과 수입"으로 푼다). 한 문장에 층이 둘이면 안쪽 묶음은 "와/과"로 잇거나 괄호로 감싸고 바깥만 쉼표로 가른다("민수와 영희, 선미와 준호가 짝이 되어"). 더 앞선 원칙은 나열 자체를 줄이는 것이다. 세 개씩 늘어놓는 버릇이 AI 글의 신호이므로, 늘어놓기 전에 상위어로 묶거나 항목을 덜어 낸다. 개조식 동사 나열은 '및'을 마지막 항목 앞에 한 번만 쓴다.

## 차단 8 문장 완결성

- 줄글에서 조사와 어미 생략 금지(개조식은 차단 3을 따른다). 부사, 보조사, 선어말어미, 보조 용언을 써서 뜻 관계를 분명히 한다. 예 : "이 결정은 이후 중요 정책이 갈리는 자리. 컨텍스트 압축 전 신중 반영한다." → "이 결정은 이후 중요한 정책에 지속적으로 영향을 주기 때문에, 컨텍스트가 압축되기 전에 신중히 반영합니다." → "지금 답변해주신 결정 사항은 이후 중요한 정책에도 지속적으로 영향을 미치기 때문에, 컨텍스트가 압축되기 전에 미리 신중하게 반영해 놓겠습니다."
- 줄글 문장은 명사구, 부사구, 연결어미로 끝내지 않고 서술어와 종결어미로 끝낸다(헤딩, 목록, 표 셀 제외)
- 뜻을 담은 문장 성분 생략 금지. 읽는 사람이 맥락 없이도 뜻을 알 수 있어야 한다. 관형격 조사 "~의"를 필요 이상으로 쓰면 뜻을 담은 성분이 빠지기 쉬우므로 유의한다. 예 : "그러면 경고가 붙습니다." → "그러면 이미 작업 중인 파일에도 경고 표지가 추가됩니다."(맥락과 정보를 충분히 제공하도록 수정) / "사본의 문구는 작업의 상황을" → "사본에 기재된 문구는 작업이 진행되는 상황을"

이 절은 snflkd/fluent-korean(MIT)에서 이 규칙집에 없던 항목만 요약해 가져왔다.

## 화면 문구 예외 (구글 슬라이드 본편, HTML 프레젠테이션)

차단 3(종결 문체)만 적용하지 않고, 사용자 덱의 쓰임별 문형 표(질문형 제목, 한다체 선언, 반말 속마음 인용, 말 걸기 습니다체, 실습 지시 "~해주세요!", 인사 ":)" 등)를 따른다. 청중 권유와 지시는 "~해 보세요"로 쓰고 "~십시오"는 쓰지 않는다. 문형표 정본 위치는 사용자의 CLAUDE.md(전역 또는 프로젝트)에 둔다. 문형표가 없으면 차단 3을 그대로 적용한다. 차단 1(호명, 의미 부풀리기, 원본에 없는 격려 문구), 차단 2, 5, 6, 7은 그대로 적용하고, 차단 8은 줄글 규칙이므로 화면 문구에는 적용하지 않는다.

## 출력 직전 셀프체크 (강제)

본문(헤딩, 표 셀, 콜아웃, 불릿 포함)에서 위 차단 1~8을 한 번 훑고 교체한 뒤 출력한다. 표 셀이라고 구어체를 허용하지 않는다.

예외 : 코드, 주석과 로그, 사용자 원문 인용, 사용자가 "구어체 OK", "원문 그대로" 지시한 경우. 채팅 답변, 진행 보고, 역질문 답변은 적용 범위 절의 기본 미적용 대상이며, 사용자의 CLAUDE.md(전역 또는 프로젝트)가 적용 대상으로 넓히면 예외 없이 차단 1~8을 지킨다.

## 자동 검수 절차

1. 분량 있는 한국어 문서(2문단 이상)는 완성 전에 `humanizer` 스킬(격식 모드)로 AI 티를 제거하고, 다듬어진 최종본만 제시한다.
2. 노션, 이메일 등 외부에 게시, 발송되는 문서는 "완료" 보고 전에 `korean-spell-check` 스킬로 맞춤법을 검수하고, 진짜 오류만 수정해 반영한다.
3. 기밀성 높은 문서는 맞춤법 검수를 생략한다(검수 텍스트가 외부 맞춤법 검사기로 전송되기 때문).
