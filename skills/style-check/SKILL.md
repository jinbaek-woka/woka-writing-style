# 문체 점검표 (style-check)

문체 점검을 규칙마다 따로 기억에 의존해 하면 규칙이 하나씩 빠지고 같은 작업이 되풀이됩니다. 이 스킬은 규칙 파일에서 점검표를 자동으로 뽑고, 판정표가 모든 번호를 다루었는지 기계로 확인하게 해 서로 다른 세션도 같은 방식으로 점검하게 합니다.

## 언제 사용하는가

- 문체 점검 또는 문체 검수를 요청받았을 때.
- 한국어 산출물(강의자료, 노션 페이지, 그림 글자, 보고서, 메일 등)의 완료 보고 직전.
- 독립 검토자에게 문체 대조를 맡길 때(점검표와 원문 전체를 함께 전달).
- 사용자가 일부 규칙만 언급했어도 규칙 전체를 같은 깊이로 점검합니다.

## 준비

- 스크립트는 이 스킬 폴더의 `scripts/` 아래에 있습니다. 표준 라이브러리만 사용하므로 설치할 것이 없습니다.
- 스크립트는 자기 위치에서 플러그인 뿌리를 찾아 `hooks/style-rules.md`와 `skills/humanizer/references/formal-mode.md`를 원천으로 사용합니다. 찾지 못하면 오류가 나므로 `--rules-root <플러그인 뿌리>`를 붙입니다.
- 현재 폴더 위쪽의 `CLAUDE.md`와 `.claude/skills/lecture-notion/SKILL.md`는 선택 원천입니다. 없으면 건너뛰며, 위치가 다르면 `--project <프로젝트 폴더>`를 붙입니다.
- 점검표(`점검표.md`, `점검표.json`)는 플러그인 폴더 안에 만들지 않습니다. `--out`으로 작업 폴더를 지정합니다.
- 원천 파일이 바뀌면 점검표는 다음 실행 때 자동으로 다시 만들어집니다. 새로 생긴 `##` 절은 번호가 자동으로 붙습니다(점검 방법 절은 CM, 그 밖의 새 절은 SX).

## 순서

각 단계의 명령 예와 판정표 틀은 `references/판정표_틀.md`에 있습니다.

1. 낱말 후보 확인 : `lint_style.py`로 산출물 파일을 검사합니다. 찾은 것은 위반 후보이므로 문장을 읽고 판정합니다.
2. 점검표 전체 판정 : `build_checklist.py`로 만든 점검표의 모든 번호를 산출물 전체와 대조해 판정표를 작성합니다. 열은 번호, 판정, 놓친 곳이며 한 행에 번호 하나를 작성합니다. 판정 칸은 지킴, 놓침, 해당 없음 가운데 하나로 시작합니다.
3. 재검수 : 놓침으로 판정한 곳을 고친 뒤 고친 문장을 점검표 전체로 다시 대조합니다. 건수가 많은 규칙만 골라서 하지 않습니다.
4. 누락 검사 : `check_coverage.py`에 판정표를 넣어 "누락 없음"이 나올 때만 완료 보고를 합니다. "검수 미완료"가 나오면 빠진 번호를 채우고 다시 검사합니다.

그림 글자를 검토할 때는 점검표를 만들 때와 누락 검사 때 모두 `--figure`를 붙입니다(그림 규격 LG 번호 포함).

## 판정 원칙

- 원래 있던 글자와 다른 자료에서 가져온 글자도 대상입니다. "원본과 같다", "본문과 같다"는 위반을 남길 이유가 아닙니다. 원본과 달라지는 곳은 보고에 작성합니다.
- 낱말 검사에 걸리지 않아도 문장 뼈대, 낱말 결합, 격식 낱말, 나열, 문장 완결성은 "팀장에게 말로 보고한다면 이렇게 말하는가"를 기준으로 문장을 읽어 판정합니다.
- 분량이 많으면 독립 검토자에게 점검표와 원문 전체를 넘겨 판정표를 받고, 최종 판정은 직접 합니다.
- 판정표의 판정 칸을 비우지 않습니다. 해당하는 글이 없으면 "해당 없음"으로 작성합니다.

## 보고

- 보고에는 실제로 한 점검만 작성합니다. 낱말 검사만 했으면 낱말 검사만 했다고 작성합니다.
- 누락 검사의 실제 출력(점검표 항목 수, 판정한 번호 수, 빠진 번호 수)을 그대로 옮깁니다. 숫자를 짐작해 적지 않습니다.
- 규칙 파일, 격식 모드 파일, CLAUDE.md는 이 스킬이 고치지 않습니다. 규칙 변경이 필요하면 사용자에게 보고합니다.

## 한계

- 낱말 검사는 후보만 찾습니다. 비유, 번역체 뼈대, 나열, 문장 완결성은 사람이 읽어야 판정됩니다.
- 노션 블록 목록 형식(`[블록 ID] 종류: 글`)을 읽을 수 있고, 콜아웃 줄은 마침표 후보에서 뺍니다. 코드 줄은 시간 표현(오늘, 어제, 내일, 방금, 아까), 줄표, 가운뎃점만 검사하고 나머지 검사는 건너뜁니다.
- 점검표 번호는 원천 파일의 줄 순서에 따라 붙으므로, 원천이 바뀌면 같은 번호가 다른 규칙을 가리킬 수 있습니다. 판정표는 점검표를 만든 직후에 작성합니다.
